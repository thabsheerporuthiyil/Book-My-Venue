# Infrastructure Provisioning with Terraform

This directory holds the **Infrastructure as Code (IaC)** templates for provisioning the cloud resources required to host the Book My Venue platform.

---

## Folder Layout

We structure Terraform configurations by environment and module to ensure high scalability:

```text
infrastructure/terraform/
├── modules/
│   ├── vpc/                    # Networking (Subnets, Security Groups, NAT Gateways)
│   ├── ecs_eks/                # Container Orchestration (AWS ECS / EKS)
│   ├── rds_postgres/           # Database layer (Amazon RDS / Aurora / Neon settings)
│   ├── elasticache_redis/      # Caching layer (Redis ElastiCache clusters)
│   └── route53_dns/            # DNS and Routing
└── environments/
    ├── staging/
    │   ├── main.tf             # Entrypoint for staging deployment
    │   ├── variables.tf
    │   └── terraform.tfvars
    └── production/
        ├── main.tf             # Entrypoint for production deployment
        ├── variables.tf
        └── terraform.tfvars
```

---

## Lifecycle Execution Flow

1. **State Management**: State files (`terraform.tfstate`) MUST be stored in a remote backend (e.g. AWS S3 bucket) with DynamoDB locks to prevent concurrent mutations.
2. **Environment Isolation**: Always run commands from inside specific environment subdirectories (e.g., `environments/staging/`):
   ```bash
   terraform init
   terraform plan -out=tfplan
   terraform apply tfplan
   ```
3. **Downstream Configuration**: Outputs generated by Terraform (such as database host endpoints, load balancer DNS name, security tokens) are used by Ansible to finalize application setup.
